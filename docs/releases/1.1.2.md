# Silencer 1.1.2

Silencer 1.1.2 adds the separately downloadable browser web-chat extension and hardens its protocol v3 request ledger and restoration mappings.

## Browser extension

The [Silencer Web Chat 1.1.2 ZIP](https://github.com/liuarui/silencer/releases/download/v1.1.2/silencer-webchat-1.1.2.zip) supports text conversations on ChatGPT, Gemini and DeepSeek. Extract the ZIP, open `chrome://extensions` in Chrome or Chromium, enable Developer mode and select **Load unpacked**. Configure the Silencer gateway URL and extension token in the extension settings, then grant access to the sites you use. The gateway's browser-extension integration must be enabled.

The supported scope is text conversations. File uploads, images, audio, WebSocket traffic and other chat sites are not covered. Official Docker images expose the extension API with the bridge disabled by default; enable it explicitly in gateway settings. `SILENCER_EXTENSION_DISABLED=1` hard-disables the API. The extension source is reviewed in [`extension/`](https://github.com/liuarui/silencer/tree/v1.1.2/extension); CI builds its independent ZIP and SHA-256 checksum from the tagged source. Dedicated console UI remains outside this release.

## Gateway and mapping changes

- Extension handshake protocol v3 persists browser response mappings across the separate mask and restore requests.
- Mapping scope combines the authenticated extension token, browser installation identity and page host; mappings are isolated between origins and installations.
- Completed logical text values flush their own restoration channel, so independent protocol fields cannot be accidentally concatenated into a placeholder.
- Invalid value-completion flags are rejected without consuming the active restoration session.
- Existing reverse-proxy routes, named upstreams and stored data remain compatible.
- Docker images expose the extension API for explicit opt-in use; the bridge remains disabled until enabled by an administrator.

## Other packages

Docker tags `liuarui/silencer:1.1.2`, `1.1` and `latest` provide `linux/amd64` and `linux/arm64`. Native capture bundles continue to cover Windows x64, Linux x64, macOS Intel and Apple Silicon. Docker images and native bundles are published by the verified GitHub Actions release workflow.

For capture setup and platform limits, see [capture requirements](../CAPTURE.md). Windows/Linux system permissions and proxy coexistence still require validation on representative user systems; CI package checks do not establish that every third-party proxy or application is protected.
